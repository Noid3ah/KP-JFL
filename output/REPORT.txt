  1. HOW TO COMPILE AND RUN THE APPLICATION
================================================================================

REQUIREMENTS
  - A C++17-compatible compiler:
      Windows  : MinGW-w64 (g++) — recommended via MSYS2 or WinLibs
      macOS    : Xcode Command Line Tools (clang++)
      Linux    : GCC/G++ (sudo apt install g++)
  - No third-party libraries are required — standard C++17 only.

STEP-BY-STEP (All Operating Systems)
  ─────────────────────────────────────────────────────────────────────────────
  Step 1 — Open a terminal in the project folder.

      Windows  : Open PowerShell or Command Prompt, then navigate:
                   cd path\to\JamaicanFootballLeague_Full

      macOS    : Open Terminal, then navigate:
                   cd ~/path/to/JamaicanFootballLeague_Full

      Linux    : Open a terminal, then navigate:
                   cd ~/path/to/JamaicanFootballLeague_Full

  ─────────────────────────────────────────────────────────────────────────────
  Step 2 — Compile the program.

      Windows (MinGW / g++):
        g++ -std=c++17 -Wall main.cpp -o main.exe

      macOS / Linux (clang++ or g++):
        g++ -std=c++17 -Wall main.cpp -o main

  ─────────────────────────────────────────────────────────────────────────────
  Step 3 — Run the program.

      Windows:
        .\main.exe

      macOS / Linux:
        ./main

  ─────────────────────────────────────────────────────────────────────────────
  Step 4 — (Optional) Run the automated test suite.

      Windows:
        .\main.exe --test

      macOS / Linux:
        ./main --test

  ─────────────────────────────────────────────────────────────────────────────

================================================================================
  3. OBJECT-ORIENTED DESIGN RATIONALE
================================================================================

1. ENCAPSULATION
   All data members are declared private or protected. Access is only possible
   through validated getters and mutators. For example, team points cannot be
   directly modified — they update exclusively through
   FootballTeam::recordMatch(gf, ga, points).

2. INHERITANCE
   Person Hierarchy (Person 2):
     Person (Abstract)
       ├── Player          — position, jersey number, goals
       ├── Coach           — qualifications, role, years of experience
       ├── MatchOfficial   — officiating role, grade, availability
       ├── LeagueCommissioner — team approval, suspension, match inspection
       └── Spectator       — fan loyalty, email, tickets bought

   Product Hierarchy (Person 4):
     Product (Abstract)
       ├── Merchandise     — size, team association, material
       └── FoodItem        — beverage flag, expiry date, perishability

3. POLYMORPHISM
   - Person:  virtual void displayInfo() const = 0;
     Overridden by Player, Coach, MatchOfficial, Commissioner, Spectator.
   - Product: virtual void displayProduct() const = 0;
     Overridden by Merchandise and FoodItem.

4. ABSTRACTION
   Both Person and Product are high-level abstract interfaces. Concrete
   implementation details are hidden from callers such as StadiumShop and
   LeagueCommissioner.

5. RELATIONSHIPS
   Composition (strong ownership):
     FootballTeam     *-- Player / Coach
     FootballLeague   *-- Fixture
     Fixture          *-- MatchResult / Ticket
     StadiumShop      *-- Product

   Aggregation (independent lifecycle):
     FootballLeague   o-- LeagueCommissioner
     Fixture          o-- MatchOfficial

   Association:
     Fixture          --> Stadium & FootballTeam
     Ticket           ..> Spectator

  4. MANDATORY BUSINESS RULES & EXCEPTION HANDLING
================================================================================

  All exceptions inherit from JFLException (which derives from
  std::runtime_error), giving the system a cohesive, strongly-typed
  exception hierarchy.

  Rule  1  Unregistered or suspended teams cannot be scheduled.
           → TeamNotEligibleException

  Rule  2  A team cannot play in two fixtures at the same date and time.
           → SchedulingConflictException

  Rule  3  A stadium cannot host two fixtures at the same date and time.
           → SchedulingConflictException

  Rule  4  A match official cannot be booked for conflicting fixtures.
           → OfficialConflictException

  Rule  5  Match scores cannot be negative numbers.
           → InvalidScoreException

  Rule  6  A fixture cannot be marked complete without a recorded score.
           → ResultRequiredException

  Rule  7  Players must be at least 16 years old.
           → InvalidAgeException

  Rule  8  Coaches must be at least 21 years old.
           → InvalidAgeException

  Rule  9  No duplicate jersey numbers within the same team.
           → PersonnelException

  Rule 10  Ticket sales cannot exceed stadium seating capacity.
           → CapacityExceededException

  Rule 11  Shop transactions cannot complete if payment is insufficient.
           → InsufficientPaymentException

  Rule 12  Shop transactions cannot complete if items are out of stock.
           → OutOfStockException

  5. MATCH-DAY FINANCE & FILE PERSISTENCE
================================================================================

GCT CALCULATION (15% Jamaican General Consumption Tax)
  Subtotal    = Σ (UnitPrice × Quantity) for all items in cart
  GCT (15%)   = Subtotal × 0.15
  Total       = Subtotal + GCT
  Change      = CashTendered − Total

  If CashTendered < Total, the transaction rolls back inventory and throws
  InsufficientPaymentException.

FILE PERSISTENCE (pipe-delimited flat text, auto-synced on every change)
  kpfl_users.txt          — Saved login accounts (username|password|role|name)
  kpfl_teams.txt          — Team registration, standings, suspension status
  kpfl_stadiums.txt       — Stadium ID, name, location, capacity, condition
  kpfl_shop_inventory.txt — Item category, ID, name, unit price, stock level
  kpfl_shop_receipts.txt  — Receipt ID, customer, subtotal, GCT, total, change

  All five files are loaded automatically on program startup and written
  whenever data changes, so no information is lost between sessions.

================================================================================
  6. THREE MANAGEMENT REPORTS (Specification Section 4.11)
================================================================================

REPORT 1 — Top Goal Scorers (Golden Boot Race)
  Scans all player records across every registered team.
  Sorts players descending by goals scored.
  Displays rank, player name, team, jersey number, and goal tally.

REPORT 2 — Match Attendance & Stadium Capacity Utilization
  Evaluates each fixture and its venue.
  Computes capacity versus tickets sold.
  Outputs percentage occupancy for safety and marketing analytics.

REPORT 3 — Team Registration & Squad Status Summary
  Summarises each club's parish location, active squad size, and
  registration status (Active, Pending Approval, or Suspended).
